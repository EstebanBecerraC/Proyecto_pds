# HU-05: Editar campaña

Como creador de una campaña, quiero modificar los datos de mi campaña en Borrador para corregir o completar la información antes de activarla.

## Alcance implementado

- Solo el creador autenticado puede editar su campaña.
- Solo se permite editar campañas en estado **Borrador**.
- El formulario precarga título, descripción, categoría, meta y fecha límite, y muestra la imagen actual.
- Se puede conservar la imagen existente o reemplazarla por JPG, PNG o WebP de hasta 5 MB.
- Guardar modifica la campaña existente y vuelve al detalle con un mensaje de confirmación.
- Cancelar vuelve al detalle sin guardar.
- Se mantienen dueño, estado, recaudación, identificador y fecha de creación.
- El servidor valida sesión, origen, permisos, estado, campos e imagen aunque se intente evitar la interfaz.

## API

`PUT /api/campaigns/:id` recibe un formulario multipart con `title`, `description`, `category`, `goal` y `deadline`. El archivo `image` es opcional durante la edición. No se necesita `creationKey`.

| Respuesta | Situación |
|---|---|
| 200 | Cambios guardados |
| 400 | Formulario mal formado |
| 401 | Sesión ausente o vencida |
| 403 | Origen no permitido |
| 404 | Campaña inexistente o ajena |
| 409 | Estado no editable, incluido un cambio de estado durante el guardado |
| 422 | Campos o imagen inválidos |

## Pruebas automatizadas

`bun test` ejecuta las suites existentes y `server/campaign-edit.test.js`, que agrega 10 casos para guardado, conservación y reemplazo de imagen, permisos, estados, validaciones, origen, sesión, cuerpo mal formado y activación durante el procesamiento del formulario.

Cypress prueba el flujo completo contra la API y SQLite reales. Los usuarios y las campañas se crean para cada ejecución; conviene utilizar una base de datos exclusiva para pruebas.

| Caso | Escenario |
|---|---|
| HU05-CY-01 | Precarga, edición y persistencia sin reemplazar imagen |
| HU05-CY-02 | Seleccionar y guardar una nueva imagen |
| HU05-CY-03 | Validaciones y conservación de datos guardados |
| HU05-CY-04 | Cancelar sin guardar |
| HU05-CY-05 | Bloqueo de campañas activas y canceladas por URL directa |
| HU05-CY-06 | Bloqueo de usuario ajeno por URL directa |

### Ejecutar Cypress en Windows / PowerShell

Instalar dependencias desde la raíz del repositorio:

```powershell
bun install
```

Terminal 1: levantar la API con una base de datos exclusiva para pruebas:

```powershell
$env:DATABASE_PATH = "data/hu05-e2e.sqlite"
bun run dev:server
```

Terminal 2: levantar el frontend:

```powershell
bun run dev
```

Terminal 3: ejecutar los escenarios:

```powershell
bun run test:e2e --spec cypress/e2e/HU05-editar-campana.cy.js
```

También se puede abrir la interfaz de Cypress con `bun run test:e2e:open`.

Cypress requiere Node.js compatible con su versión. Si su aplicación no se descargó durante la instalación, ejecutar `bunx cypress install` y luego repetir la prueba. La API limita los intentos de autenticación a 20 por minuto; si se realizan varias ejecuciones seguidas y aparece 429, esperar un minuto.

`DATABASE_PATH` es opcional. Cuando no se define, la aplicación utiliza `data/app.sqlite` como antes. Para volver a esa base en la misma terminal, detener la API y ejecutar `Remove-Item Env:DATABASE_PATH` antes de reiniciarla.
