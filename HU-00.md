# HU-00A / HU-00B: inicio de sesión y registro

Requiere Bun. SQLite está integrado en Bun y no requiere instalar un servicio separado.

## Desarrollo

En una terminal ejecutar `bun run dev:server` para iniciar la API en el puerto 3000.
En otra terminal ejecutar `bun run dev` para iniciar Vue con Vite.
Abrir http://localhost:5173.

La base de datos se crea automáticamente en `data/app.sqlite`. No se incluye en Git.
Para instalar dependencias en un clon nuevo: `bun install`.

## Funcionalidad

Registro con nombre (2–80 caracteres), correo único y contraseña (8–128 caracteres).
Después del registro se crea la sesión automáticamente y se abre Inicio, sin volver a ingresar las credenciales.
La cuenta y su sesión se guardan en una sola transacción.
Los correos repetidos se rechazan sin distinguir mayúsculas ni espacios en los extremos.
El mensaje exacto "Este correo ya está registrado" aparece debajo del campo de correo.
Los campos vacíos se resaltan y muestran "Campo obligatorio" junto a cada uno.
El login rechaza credenciales incorrectas con "Correo o contraseña incorrectos", mantiene la pantalla y conserva el correo escrito.
La regla de contraseña de 8–128 caracteres se aplica al registro; una contraseña corta no vacía en el login se verifica como credencial.
Login, consulta de sesión y logout mediante cookies HttpOnly y SameSite=Lax.
Las sesiones duran siete días y se almacenan en SQLite con el hash del token.
Las contraseñas se guardan con Argon2id.
Se admiten veinte solicitudes de registro/login por minuto por IP.
El límite se mantiene en memoria y se reinicia junto con el servidor.

## Verificación

- `bun test`: pruebas de la API con bases de datos aisladas en memoria.
- `bun run build`: compila la interfaz en `dist/`.
- `bun run preview`: sirve la interfaz compilada; requiere también la API.

## API

- POST /api/auth/register: name, email, password. Devuelve 201 con `user` y la cookie de sesión.
- POST /api/auth/login: email, password.
- GET /api/auth/me: usuario de la sesión actual.
- POST /api/auth/logout: invalida la sesión.

Para otro origen configurar APP_ORIGIN en el servidor. PORT cambia el puerto de la API;
si cambia, actualizar el proxy de Vite. Para despliegue se requiere servir la interfaz
y /api bajo el mismo origen mediante HTTPS y usar NODE_ENV=production para cookies Secure.
No incluye recuperación de contraseña ni verificación de correo.

## Pantallas

- /#/: landing pública con presentación de CrowdStarter y explicación del crowdfunding.
- /#/register: registro de usuarios; al terminar lleva a Inicio con sesión iniciada.
- /#/login: acceso; al terminar lleva a la homepage.
- /#/home: homepage provisional, requiere sesión. Conserva el acceso al recargar.
- Cerrar sesión invalida la sesión y vuelve a la landing.

Las vistas públicas y privadas están separadas en componentes Vue. La navegación
usa fragmentos de URL y admite los botones atrás y adelante del navegador.

## Comprobación manual de los criterios

1. En Login, enviar ambos campos vacíos: ambos muestran "Campo obligatorio" y se resaltan. Repetir omitiendo solo uno.
2. Ingresar un correo registrado y la contraseña incorrecta `123`: aparece "Correo o contraseña incorrectos", se conserva el correo y se permanece en Login.
3. Ingresar las credenciales correctas: se abre Inicio; al recargar se conserva la sesión.
4. Crear una cuenta con correo nuevo y datos válidos: se abre Inicio directamente; al recargar se conserva la sesión.
5. Cerrar sesión e intentar registrarse con ese mismo correo: aparece "Este correo ya está registrado" debajo del correo y no se crea otra cuenta.

Las pruebas Bun cubren sesión automática, persistencia, duplicados, validaciones por campo, credenciales cortas incorrectas y reversión ante fallos de sesión.
La prueba Cypress existente de HU05 espera ahora Inicio después del registro. Su ejecución se reserva para la revisión E2E previa a la release.
